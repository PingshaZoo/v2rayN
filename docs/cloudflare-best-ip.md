# Cloudflare Best IP 测速

该功能在 v2rayN 的 Windows 和跨平台桌面版主菜单中打开独立窗口。测试连接直接拨向候选 Cloudflare IPv4 地址，同时使用填写的域名作为 TLS SNI 和 HTTP Host。

## 首次使用

1. 在“测速”页填写自己的源站 SNI（可每行一个）、延迟测试路径和下载路径。两个路径应以斜杠开头，返回 HTTP 200；下载路径应返回足够大的未压缩文件。edge 模式只用 /cdn-cgi/trace 测延迟，仍需要下载路径用于第二阶段测速。
2. 在“数据源”页填写至少一个历史结果 URL、IP 列表 URL 或域名列表 URL。历史结果为 JSON 数组，条目至少包含 ip，可附 speed_kb_s。IP 列表可以是包含 IPv4 的文本；域名列表是 JSON 数组或含 domains 数组的 JSON 对象。
3. 点击“开始测速”。先并发探测延迟，再串行测下载速度，合格 IP 统一按速度排序，取 Top N。表格显示 SNI、Cloudflare 节点、延迟、速度、HTTP 丢包和来源。可随时点击“停止”。

除公开 Cloudflare IPv4 CIDR 及其官方查询接口外，程序不预填历史结果、IP 列表、域名列表或上报地址。安装包不会包含维护者的个人服务地址。已保存的本地设置不会被清空。

## 结果与上报

测速不需要节点密码；此功能只显示测速结果，不创建、导入或修改代理节点。既有节点保持不变。

上报地址仅由使用者自行填写。点击“上报”后才会向这些地址发送本次结果；开始测速不会自动上报。

## 排查

- 无候选 IP：检查数据源 URL 可访问、内容格式，以及 IP 是否落在 Cloudflare IPv4 网段内。
- 有延迟但无合格结果：检查下载路径是否返回 HTTP 200、未压缩正文及足够字节；再核对最低速度阈值。
- TLS / HTTP 失败：核对 SNI、证书验证设置和路径。探测使用直连候选 IP 的套接字，不经过应用层 HTTP 代理；系统级 TUN 或网络策略仍可能影响链路。
